# 比较基线与同步范围

## 1. 起点如何确认

行为来源固定为 `ark-endfield-3rd-test` 的 `26a49e814f0570e050a19b726b3ba689d282aa3b`，origin为 `endfield-calc/factoriolab`。比较和验收使用该提交，不以本地其他分支或远端默认分支推定范围。

沿该分支历史，第一个 Endfield 专属改动是 `0a667756e71e332ba613a62549bcd6ceb08e80d7`，标题为“make it Arknights: Endfield exclusive”。它的直接父提交是 `7b46c4389f257a57aaa23b3094c556ae1a39d7a9`，对应旧上游 v3.9.2 的修复。这比用仓库创建时间、现有默认分支或分支名称推测 fork 点可靠。

证据：[首次专属提交](https://github.com/endfield-calc/factoriolab/commit/0a667756e71e332ba613a62549bcd6ceb08e80d7)、[fork 起点](https://github.com/endfield-calc/factoriolab/commit/7b46c4389f257a57aaa23b3094c556ae1a39d7a9)。

## 2. 后续同步不能算作本地定制

在目标分支的可达历史内，存在如下上游合入记录：

| 本项目提交             | 历史事件                               | 范围判断                                           |
| ---------------------- | -------------------------------------- | -------------------------------------------------- |
| `9da20773`、`0f064e67` | 合入当时的main                         | 本地功能差异中包含上游正常演进                     |
| `141e3642`             | 合入旧上游 `b9c6371e`                  | 不重新移植 Factor Y 等非 Endfield 功能             |
| `8704b97c`             | 合入旧上游 `b8c1f021`                  | 最近一次完整 merge 进目标历史的旧上游检查点        |
| `0e8f7fc5`             | 标题为 cherry-pick upstream 的后续提交 | 包含步骤层级修复等通用逻辑，须检查新版是否已经具备 |

这里核查的是**目标分支本身包含的历史**，没有把其他本项目分支的后来功能纳入范围。

`b8c1f021` 的标题为修复ngsw-config。它与原 fork 起点之间共有 7 个上游提交。原起点至目标共有 184 个可达新增提交，检查点至目标共有 177 个；这些都是 Git 历史计数，包含 merge 和数据更新，不能称为 184/177 个独立定制需求。

## 3. 上游设计基线

上游仓库为 `factoriolab/factoriolab`，默认分支main，设计分析使用以下固定快照：

- `00bdb91c2442cd8d715501b9469cec115735645f`；
- 提交标题为修正Satisfactory配方与堆叠数量；
- 关键大改为FactorioLab 4.x：`11e7be16d84595b683da5de981b8fa54ba4a1697`；Angular22升级提交为 `3fce931ca8c64319f4f500d8a5db88e2bfb02e5f`。

证据：[上游设计基线](https://github.com/factoriolab/factoriolab/commit/00bdb91c2442cd8d715501b9469cec115735645f)、[4.x 大改](https://github.com/factoriolab/factoriolab/commit/11e7be16d84595b683da5de981b8fa54ba4a1697)、[Angular 22 升级](https://github.com/factoriolab/factoriolab/commit/3fce931ca8c64319f4f500d8a5db88e2bfb02e5f)。

有一项影响比较方式的事实：GitHub compare 返回两分支没有共同祖先；在非浅克隆的独立上游仓库中，结合本地完整对象再运行 merge-base，同样没有结果，退出码为 1。目标历史根为 `9d8114e3ab317a7eebab44598f4b692bc0fead19`，当前上游根为 `7cbe9521fbd6fa7f9b105d93ea7d9242f0263485`。上游历史中同标题的旧修复也使用不同 SHA，例如原 fork 修复在新历史中为 `51b89f6e...`。

这些证据确认了历史对象身份不同，**不能仅据此断言是谁、何时、以何种操作改写了历史**。本方案不依赖这一原因，也不使用允许无关历史合并来处理迁移。

## 4. 差异口径

| 比较                          | 文件数 | 文字增删          | 用途                                   |
| ----------------------------- | ------ | ----------------- | -------------------------------------- |
| 原 fork 起点 → 目标提交       | 344    | +73,737 / -4,958  | 满足“与当时 fork 时相比”的全量范围核查 |
| 已合入旧上游检查点 → 目标提交 | 340    | +73,558 / -14,386 | 辅助识别本项目净定制                   |

以上采用 Git 默认重命名识别。关闭重命名识别会分别得到 345 和 341 个文件，因为 `src/data/dsp/defaults.json` → `src/data/aef/defaults-spa.json` 被拆成删、增；不是额外发现了功能。

原口径涉及 80 个 `src/app` 文件，检查点口径涉及 73 个。后者中测试文件共有 16 个（按全部路径中的 `.spec.ts` 统计）。JSON 大文件行数、二进制素材、历史残留样例均不等价于产品复杂度。

原始差异里以下文件与旧上游检查点相同，不能当作尚需搬迁的独立 Endfield 定制：belt-overlay、header SCSS、tech-picker、tooltip、models/defaults、preset 枚举及其测试，以及 `src/styles.scss`。文件级说明见[逐文件索引](07-file-diff-index.md)。混合了上游与本地改动的文件仍须逐项判断，不能因为有一个上游来源就整文件排除。

## 6. 复查方式

后续可用以下少量只读命令复核范围；上游对象应先在独立审计仓库中取得：

```text
git show 0a667756^ --no-patch
git diff --name-status 7b46c438 26a49e81
git diff --name-status b8c1f021 26a49e81
git log --first-parent --merges ark-endfield-3rd-test
git merge-base <上游固定SHA> 26a49e81
```

Git祖先关系和来源提交属于范围证据；实现方案以03和09的最终接点设计为准，不按旧提交逐个重放。外部数据生成器、部署账户和Secrets权限需要实施时验证。

首次迁移建立新的上游血缘，后续同步走正常上游合入流程；只限制首次迁移不能把旧分支merge进来，不禁止迁移完成后吸收上游更新。业务等价与已知缺陷修复的验收边界见02和04。
